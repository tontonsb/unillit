**Date:** 2026-08-30 · **Version:** 1.0.7 · **Scope:** whole app
**Status:** findings recorded, none fixed

Run via `/impeccable audit`. Evidence: static detector (29 findings), `npm run
build` output, rendered measurement at 390×844 and 1440×900 through the
Playwright MCP server, computed-style and `getBoundingClientRect` sampling,
offline contrast computation. Supersedes [audit-2026-08-09.md](audit-2026-08-09.md).

**Priorities are ranked by impact on a sighted learner doing the core task**,
per [How these are prioritised](audit-2026-08-09.md#how-these-are-prioritised).
That framework is unchanged and is not restated here.

**Down 1 from 2026-08-09, and nothing regressed.** Four of that audit's findings
landed (`lang` BCP-47, image intrinsic dimensions, `transition: all`,
reading-tips rem clamp) and no fixed item came undone. The point is entirely a
newly found mobile layout break on the home page that the last pass missed —
it checked for *overflow* at 390px, found none, and moved on; the failure is a
fixed two-column grid squeezing text, which produces no overflow.

Two clusters still carry most of the real impact, both unchanged since August 9:
**badge legibility** and **touch targets**. The new material adds a third:
**the home page below the fold on mobile**.

### Implementation Integrity Verdict — PASS

The system is real and still holds under measurement:

- **Zero** `box-shadow`, `filter`, `backdrop-filter`, gradient, `will-change` or
  `@keyframes` anywhere. The No-Shadow Rule remains a held position.
- **Zero** `z-index`. Stacking is still pure document order.
- `npm run type-check` and `npm run lint:stylelint` pass clean. ESLint reports 14
  warnings, all `quotes` on font-family strings that legitimately contain
  apostrophes — a config gap (`avoidEscape`), not a code problem.
- No literal `font-size` survives in a component; the `--fs-*` ramp holds.
- DESIGN.md's contrast positions verify. White on Signal Teal measures 4.06:1
  WCAG, which the doc already records as APCA Lc −72.8 and fine.

The detector's 29 findings resolve to **1 real cluster + 6 false positives**,
the same split as last time. The four `design-system-font` hits (`Lora
Variable`, `Noto Sans Thai Variable`, `Noto Serif Thai Variable`, `Trirong`) are
all declared in DESIGN.md's `typography.scriptFonts` — the detector does not
read the nested arrays. The `side-tab` hit on `.prose blockquote` is DESIGN.md's
documented callout. The 23 `design-system-color` hits in `CharBadge.vue` are
**all real** and are finding 2.

## Findings

Tick these off as they land.

### P1 — fix before release

- [x] **1. Home's "Suggested approach" collapses to 115px columns on mobile** — NEW
  `src/views/HomeView.vue:140` (`.approaches`)
  `grid-template-columns: 1fr 1fr` with no fallback at any width. Measured at
  390×844: the grid resolves to **135px + 135px**, each `<li>` is **115px wide at
  16px type** and wraps to **11 lines** — roughly seven characters per line. The
  two strategy lists are the page's instructions for how to use the product, and
  they are the first thing below the script index.

  It produces no horizontal overflow, which is why the last pass missed it:
  `documentElement.scrollWidth` is 390 at 390. Nothing is clipped; the measure is
  simply destroyed, in a system whose typography doctrine is built on measure.

  `ThaiAlphabet.vue:234` (`.two-col`) is the same construct and should be checked
  in the same pass; it holds up better because sheet cells are 56px minimums, but
  it has the same missing fallback.

  **Fix:** `repeat(auto-fit, minmax(min(100%, 15rem), 1fr))`. No media query —
  DESIGN.md's one-breakpoint rule and "reach for `clamp()` first" both point here.

- [ ] **2. CharBadge runs a second, foreign palette at illegible size** — carried, old 1
  `src/scripts/thai/CharBadge.vue:35-65`
  **Unchanged and re-measured at 390px:** badge type renders at **6.6px** inside a
  12×12 chip; the `.section-note` legend row at **8.25px**; sheet base at its 11px
  floor. 17 hard-coded colours across six hues, several literal Tailwind defaults.

  Contrast inside the chips is 4.42–7.57:1 — `.low`/`.open` at **4.42** is the one
  AA miss, already recorded in `docs/badge-palette-options.md`. The type is
  unreadable at any of those ratios, which is why size is the half that matters.

  Still the single highest-value fix available, for the reason the last audit
  gave: it is the loudest thing on the sheet and it inverts the Specimen Rule on
  the one surface where the glyph most needs to win.

- [ ] **3. Seven of 25 language badges fail WCAG AA** — carried, old 2
  `src/components/LangBadge.vue:51-58` (`textOn`)
  **Unchanged.** `textOn()` still uses the YIQ formula with a `0.6` threshold
  rather than comparing both candidates, and still picks the worse colour five
  times (`be`/`kv` 2.53, `bua` 2.26, `bg`/`ce` 3.40). Measured table and the fix
  are in the previous audit; recipes are in `docs/badge-palette-options.md`.

### P2 — next pass

- [ ] **4. Touch targets below the 24px minimum** — WCAG 2.5.8 (AA) — carried, old 3
  `src/scripts/thai/ConsonantPicker.vue:31` (`.cons-btn`)
  Re-measured at 390px: `.cons-btn` is **22×17px** with a **2px** gap, so it fails
  both the size minimum and the spacing exception that could have rescued it.

  **`.pill` has resolved** — it now measures exactly **24×62px** and passes. So has
  `.link-btn`. `.cons-btn` is the only remaining failure, plus `.pill.small` in
  the stats filter bar, which computes to ~20.6px (login-gated, so measured from
  the CSS rather than in the page).
  **Fix:** real padding or a transparent hit-area pseudo-element on `.cons-btn`;
  `min-height: 24px` on `.pill.small`.

- [ ] **5. Sheet type ignores the reader's font-size setting** — WCAG 1.4.4 — carried, old 5
  `src/assets/sheet.css:11` — `clamp(11px, 0.75vw, 14px)`
  **Half landed.** `reading-tips.css:10` now clamps in rem against the panel
  container (`clamp(var(--fs-chrome), 2.1cqi, var(--fs-prose))`). `sheet.css` is
  still on a px basis, so raising the browser font size changes nothing on the
  densest surface in the product, and everything nested in `em` inherits the
  freeze — this is the mechanism behind finding 2's 8.25px legend.
  **Fix:** `clamp(0.6875rem, 0.75vw, 0.875rem)` — identical at default settings,
  restores the preference.

- [ ] **6. Every route ships an identical `<head>`** — WCAG 2.4.2 (A) — NEW
  `plugins/routePages.ts:37-45`, `index.html:9-10`, `src/router/index.ts`
  The build emits **10 static route pages plus 404.html**, and every one of them
  carries `<title>Unillit</title>` and `<meta name="description"
  content="Un-illiterate yourself.">`. Verified in `dist/about/index.html` and
  `dist/scripts/thai/index.html` — byte-identical heads. The router sets no title
  on navigation either, so `document.title` reads "Unillit" on `/scripts/thai`,
  `/roadmap` and `/progress` alike (verified in the running app).

  Three consequences, in order of weight:
  - **WCAG 2.4.2 Page Titled is Level A.** Ten distinct views, one title.
  - Browser history, bookmarks and tab switching cannot distinguish any two pages.
  - Ten pages compete for the same search snippet, and a link pasted into Discord
    unfurls as "Unillit — Un-illiterate yourself" whether it points at the Thai
    sheet or the privacy page. PRODUCT.md names the GeoGuessr community as the
    distribution goal; this is the surface that reaches it.

  No Open Graph tags exist either, which is the same fix in the same place.
  **Fix:** the plugin already reads `router/index.ts` and `scripts.ts` for its
  path list — it has the script names in hand and can stamp per-route
  `<title>`/`<meta>`/`og:` while writing each shell. Add a `document.title`
  assignment on route change for the SPA half.

- [ ] **7. Roadmap step status is conveyed by colour alone, below the non-text minimum** — WCAG 1.4.1 (A), 1.4.11 (AA) — NEW
  `src/components/progress/RoadmapGraph.vue:151, 218-230`
  The 10px dot is the *only* mark carrying a step's freshness, and it is
  `aria-hidden="true"` with a `title` — so `aria-hidden` removes even the title
  from the accessibility tree and the state has no text alternative at all.
  Verified in the page: a step's full `innerText` is `"Consonants | Start from
  the basics"`, with the status nowhere in it.

  The sighted half is the part that ranks. Four states are distinguished only by
  the dot's fill and border:

  | State | Mark | Contrast vs Cell White |
  |---|---|---|
  | fresh | filled `--c-good` | 4.1:1 |
  | stale | filled `--c-warn` | 5.7:1 |
  | never | hollow, `--c-muted` border | 4.8:1 |
  | untracked | hollow, `--c-border` border | **1.46:1** |

  Measured in the page logged out, where every step is `untracked`: border
  `rgb(194, 220, 203)` on white. At 1.46:1 against a 3:1 requirement for non-text
  marks, the whole graph reads as a set of empty circles.
  **Fix:** an `.sr-only` span carrying `STATUS_LABEL` (the strings already exist),
  and a shape or weight difference so fresh/stale/never/untracked are not four
  hues of one circle. `svg.edges` should also take `aria-hidden="true"`.

- [ ] **8. One auth network round-trip per answer** — carried, old 4
  `src/composables/useStats.ts:88,110`
  **Unchanged.** `recordAnswer` still calls `supabase.auth.getUser()` before every
  insert, and `useAuth.ts` still holds the same user in a module-level ref. The
  `correctCount++`-after-await race described in the previous audit is also
  unchanged.

- [ ] **9. Supabase ships in the entry chunk** — Performance — NEW
  `src/lib/supabase.ts`, `src/composables/useAuth.ts` ← `MainMenu.vue:5`
  `dist/assets/index-*.js` is **204 kB raw / 55 kB gzip**, and 69 `supabase`
  references confirm the auth SDK is inside it. `MainMenu` imports `useAuth` at
  module scope, so the client is constructed on first paint of every route.

  PRODUCT.md is explicit that anonymous use is the full experience and that
  logging in only adds stats. For that user the SDK is downloaded, parsed and
  initialised and never used. It is the largest single item on the critical path,
  in an app whose next-largest route chunk is 22 kB.
  **Fix:** a dynamic `import()` behind first use — the login button, `useStats`,
  and the session restore. Not free (the menu needs to render a logged-out state
  first), which is why this is P2 and not P1.

- [ ] **10. A deep-linked tab opens off-screen on mobile** — carried, old 7
  `src/components/ScriptPanel.vue:142-152` (`.tabs`)
  **Unchanged** — no `scrollIntoView` exists anywhere in `src`. Scope is still
  only the `?t=` entry path; normal interaction and keyboard navigation remain
  correct.

- [ ] **11. The per-script optical correction is bypassed on two surfaces** — Theming — NEW
  `src/views/RoadmapView.vue:196`, `src/components/progress/ScriptProgressList.vue`
  Both set `.script-native { font-size: 1.1em }` — a flat constant — where
  DESIGN.md specifies `calc(1em * var(--label-scale, 1))` and calls the per-script
  microadjustment "the point". Neither passes `--label-scale`, so neither reads
  `ScriptConfig.labelScale`.

  Measured on `/roadmap`: the native name renders at **19.36px for every script**.
  Thai, Arabic, Bengali and Lao are declared `labelScale: 1.15` and get 1.1;
  Cyrillic and Greek declare none and get 1.1 where they should be 1.0. The
  correction exists because non-Latin-metric scripts lose the detail a learner is
  being taught to recognise — so this is a legibility miss on the specimen, not a
  tidiness one.
  **Fix:** bind `--label-scale` as `HomeView`, `MainMenu` and `ScriptView` already do.

- [ ] **12. `.btn-primary` is redeclared in six scoped blocks** — carried, old 9
  `QuizPanel.vue:448`, `TypeInQuiz.vue:166`, `StatsPanel.vue:337`,
  `RunsPanel.vue:127`, `ProgressView.vue:63`, plus `MultiSelectQuiz.vue:193`
  under the name `.btn-check`.
  **Was five, now six.** All six bodies are byte-identical apart from
  `ProgressView`'s added `align-self`. DESIGN.md defines `button-primary` as a
  system component and `PillControl.vue` shows the extraction this project
  already knows how to do.

- [ ] **13. Silent clipboard failure** — carried, old 10
  `src/views/ScriptView.vue:53`
  **Unchanged.** `navigator.clipboard.writeText()` has no `.catch()`; the button
  flips to "✓ Copied" regardless. `useResultShare` should be checked in the same
  pass.

- [ ] **14. Unknown paths render a blank page** — NEW
  `src/router/index.ts:5-36`
  There is no catch-all route. `404.html` is the app shell, so a mistyped or dead
  URL loads the SPA, matches nothing, and renders an empty `<main>` on a bare warm
  sheet — no message, no route back except the sidebar. An unknown *script id* is
  handled properly (`ScriptView` renders "Script not found."); an unknown *path*
  is not.
  **Fix:** a `:pathMatch(.*)*` route rendering the same treatment as
  `.not-found`.

### P3 — polish

- [ ] **15. Toggle state is not exposed to assistive tech** — carried, old 11.

  rule. **`QuizShell.vue:66-77` deserves separating out:** the quiz/stats/runs bar

- [ ] **16. Two more places dim text with opacity.** `MultipleChoiceQuiz.vue:122`

- [ ] **17. No print stylesheet exists.** DESIGN.md names The Print Test as a rule

- [ ] **18. The tabpanel is a 4049px scroll container with no `tabindex`.**

- [ ] **19. DESIGN.md drift, two items.** `typography.glyph` and

- [ ] **20. Small change, no user impact.** `RoadmapView.vue:135` applies a
  `.untracked` class that no rule matches, and that `RoadmapGraph` already
  handles through its `status` prop — dead. `public/bulgarian-vs-russian-cyrillic.png`

  `role="progressbar"`) are unchanged; 15 (`coming-soon` divs) is unchanged on
  the sidebar, though `HomeView`'s equivalent cards carry a visible "Not here

## Patterns & systemic issues

- **Compounding `em` with no floor — unchanged, and now half-cornered.** The
  reading-tips half of finding 5 landed, which proves the fix is cheap; the sheet
  half still produces every sub-9px measurement in this audit. The system has a
  documented type ramp and still no documented *minimum*. This remains the single
  highest-value fix available.
- **Fixed two-column grids are the responsive blind spot.** Both `1fr 1fr` grids
  in the codebase outside `ScriptView` (which has a breakpoint) have no fallback,
  and both are content grids rather than layout grids. The one breakpoint the
  system allows itself is spent on the panel split, which is correct — but that
  makes every other grid's fallback `auto-fit`'s job, and neither uses it.
- **State is expressed visually but not programmatically** — unchanged from the
  last audit, and now with a fifth site (the roadmap dot) where the visual
  expression is itself below threshold. That is the one instance that crosses out
  of P3, because it fails a sighted user too.
- **Route metadata was never wired.** The static-page plugin, the router and
  `index.html` each do their own job correctly and none of them owns the title.
  It is a gap between three well-built pieces, not a defect in any of them.
- **Colour drift is still concentrated in two components**, both badge
  components, both known. The remaining ~60 files are disciplined.

## Positive findings — preserve these

- **Four findings landed cleanly since 2026-08-09** and none regressed: BCP-47
  `lang` (now a real `ScriptConfig` field rather than a reused `id`), image
  intrinsic dimensions, `transition: all` named down to its properties, and the
  reading-tips rem clamp. The `lang` fix in particular closed a false positive
  from 2026-08-03 as well as a bug.
- **No shadows. No `z-index`. No `@keyframes`. No `will-change`.** All four hold
  across the whole codebase.
- **Font loading remains excellent** — 97 `@font-face` declarations, 11 families,
  and `assetsInlineLimit` explicitly disabled for fonts so `unicode-range`
  subsetting is never undone by base64 inlining. The comment explaining why is
  the kind of comment CLAUDE.md's rule is for.
- **`ScriptPanel`'s tablist** is still a correct APG implementation, with a
  documented reason for manual activation.
- **The screen-reader verdict live region** (`QuizPanel.vue:213`) is still more
  care than this product owed, and the "always rendered so it is not silent"
  comment is exactly right.
- **`prefers-reduced-motion` is honest.** The global `0.01ms` kill would be a
  finding in most codebases; here every transition is a 0.15–0.25s colour or
  width change, no animation conveys state, and the comment says why near-zero
  beats `none`. Correct as built.
- **`min-width: 0` on `.answer-input`** with a comment about intrinsic input
  width under a raised font size — a real bug prevented before it happened.
- **The accent-teal `h2` at 3.89:1 is not counted as a finding**, per DESIGN.md's
  APCA argument. Worth one note it does not have: in the reading-tips panel that
  `h2` is `1.1em` of a clamped base, so it reaches **14.1px** in a narrow panel,
  a longer stretch than the 17.6px page-prose case the concession was reasoned
  about. Information, not a demand.

## How to reproduce

```sh
# static scan
node .claude/skills/impeccable/scripts/detect.mjs --json src

# build evidence for finding 6 and finding 9
npm run build
diff dist/index.html dist/scripts/thai/index.html          # identical
grep -c supabase dist/assets/index-*.js                    # 69

# rendered measurement — preview, not dev, so vue-devtools injects nothing
npm run preview                                            # 127.0.0.1:4173
```

Findings 1, 2, 4, 7 and 11 came from `getBoundingClientRect` and computed-style
sampling at 390×844 and 1440×900. Contrast figures were computed offline with
the same WCAG implementation as `tools/contrast.mjs`.

**Wait for the remount before measuring a tab panel.** `ScriptPanel` keys its
`<component>` on `activeIndex`, so a `.click()` on a tab tears the panel down and
loads a fresh chunk. Measuring 150ms later returns a half-built DOM — an empty
panel reading `scrollHeight === clientHeight` and zero focusable children, which
is what first made finding 18 look like a keyboard trap. At 900ms the same panel
reports 1141px of content and six focusable children, and the finding drops to
P3. This is the same lesson as last audit's finding 7, in a different disguise:
measure the settled state, not the transition.

**Playwright MCP writes screenshots to the project root** unless given a path
under `.playwright-mcp/`, so check `git status` before finishing.
