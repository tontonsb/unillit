# Technical Audit — Unillit

**Date:** 2026-08-09 · **Version:** 1.0.2 · **Scope:** whole app
**Status:** findings recorded, none fixed yet

Run via `/impeccable audit`. Evidence: static detector (32 findings), rendered
browser inspection at 1440×900 and 390×844, DOM and computed-style sampling,
`Intl.getCanonicalLocales` validation, offline contrast computation over the
badge palettes. Supersedes [audit-2026-08-03.md](audit-2026-08-03.md).

**Priorities are ranked by impact on a sighted learner doing the core task**
(look at a glyph, read it), not by WCAG severity. See
[How these are prioritised](#how-these-are-prioritised).

### Implementation Integrity Verdict — PASS

The system is real and holds under measurement, not just on paper:

- **Zero** `box-shadow`, `filter`, `backdrop-filter`, gradient or `will-change`
  in the codebase. The No-Shadow Rule is a held position.
- All 11 declared font families resolve to live `@font-face` entries in
  `document.fonts` — the silent-fallback trap CLAUDE.md warns about is absent.
- `npm run type-check` and `npm run lint:stylelint` both pass clean; no console
  errors on any route visited.
- DESIGN.md's contrast positions verify correctly. `Check` (white on Signal
  Teal) measures 4.06:1 WCAG, which the doc already records as APCA Lc −72.8 and
  fine. Flagging it would have been the WCAG-only error the doc predicts.

The detector's 32 findings resolve to **1 real cluster + 6 false positives**.
The `design-system-font` hits (`Lora Variable`, `Sarabun`, `Noto Serif Thai
Variable`, `Trirong`) are picker fonts working as designed. The `side-tab` hit
on `.reading-tips blockquote` is a blockquote rule, a print convention, and
DESIGN.md's documented callout — not a card tab. The 17 `design-system-color`
hits in `CharBadge.vue` are **all real**.

## How these are prioritised

Unillit teaches visual recognition of characters. A learner who cannot see the
glyph cannot do the core task, and no amount of ARIA changes that — it is
inherent to the product, not a defect in it. So findings are ranked by what they
cost a **sighted learner**, and screen-reader parity is treated as hygiene
rather than as a release gate.

That cuts both ways, and it is why the badge findings sit at the top:

- **Contrast and type size stay high priority.** They fail sighted users
  directly, and low-vision users with magnification are a plausible audience for
  this product in a way that non-visual users are not.
- **`locl` font shaping stays a real concern.** Which letterforms a learner sees
  *is* the product.
- **`aria-pressed`, live regions and roles drop.** They cost a sighted user
  nothing; the fill colour already communicates the state.

## Findings

Tick these off as they land.

### P1 — fix before release

- [ ] **1. CharBadge runs a second, foreign palette at illegible size**
  `src/scripts/thai/CharBadge.vue:29-49`
  Two compounding problems in one 50-line file, both hitting the core task.

  *Size:* `font-size: 0.6em` compounds against the sheet's clamped base.
  Measured at 1440px — `MID`/`HIGH`/`LOW` in the legend row at **4.95px** inside
  a 9.4px chip; the same badges in cells at **6.6px**. Contrast inside the chips
  is fine (4.42–6.38:1); the type is unreadable at any contrast. 176 elements
  render below 9px on the mobile alphabet sheet.

  *Palette:* 17 hard-coded colours across 6 hues — orange, yellow, violet,
  amber, blue, red. Several are literal Tailwind defaults (`#9a3412`
  orange-800, `#fef9c3` yellow-100, `#5b21b6` violet-800, `#fcd34d` amber-300).
  In a hand-measured three-green print palette they are the loudest thing on the
  sheet: on screen the eye reaches the chips before the Thai characters, which
  inverts the Specimen Rule on the one surface where the glyph most needs to
  win.

  **Fix:** two separable changes. Set a floor around 9px so `0.6em` cannot
  compound below it. Re-map the eight states onto `--c-good`/`--c-warn`/`--c-bad`
  plus mint tints, matching the LangBadge metrics comment that already claims
  kinship.

  Note: 2026-08-03 finding 7 recorded this as a documentation gap. It is not —
  documenting a Tailwind assortment inside this palette would launder drift into
  doctrine.

- [ ] **2. Seven of 25 language badges fail WCAG AA, five avoidably** — WCAG 1.4.3
  `src/components/LangBadge.vue:51-58` (`textOn`)
  `textOn()` uses the YIQ formula with a `0.6` threshold rather than a contrast
  comparison, and picks the *worse* of the two available text colours five times:

  | Code | Language | Ground | Picked | Ratio | Other would be |
  |---|---|---|---|---|---|
  | `be` | Belarusian | `#ff7f0e` | white | **2.53** | 6.28 |
  | `kv` | Komi | `#ff7f0e` | white | **2.53** | 6.28 |
  | `bua` | Buryat | `#17becf` | white | **2.26** | 7.05 |
  | `bg` | Bulgarian | `#2ca02c` | white | **3.40** | 4.68 |
  | `ce` | Chechen | `#2ca02c` | white | **3.40** | 4.68 |
  | `ky` | Kyrgyz | `#9467bd` | white | **4.26** | 3.74 (white is best) |
  | `tyv` | Tuvan | `#7f7f7f` | white | **4.00** | 3.97 (white is best) |

  Badges also render at **7px** inside reading-tips tables. These mark which
  languages a letterform belongs to — the reader is meant to scan them against
  the glyph, so illegibility here costs the comparison the table exists to make.
  **Fix:** compute both candidates and return the higher ratio — that fixes five
  outright. `ky` and `tyv` need darker swatches; `#7f7f7f` is the mid-grey no
  text colour can rescue.

### P2 — next pass

- [ ] **3. Touch targets below the 24px minimum** — WCAG 2.5.8 (AA)
  `ConsonantPicker.vue` (`.cons-btn`), `QuizPanel.vue:383` (`.pill`),
  `ScriptView.vue:98` (`.link-btn`)
  Measured at 390px: `.cons-btn` **20×17px**; `.pill` and `.link-btn` **23px**
  tall. Inline prose links at 18px are exempt under the inline exception.
  Supersedes 2026-08-03 finding 8, which measured against the AAA 44px target;
  **2.5.8's 24px is AA, and the pills miss it by 1px.**
  **Fix:** `min-height: 24px` covers the pills without touching the density the
  Two Registers Rule protects. `.cons-btn` needs real padding or a transparent
  hit-area pseudo-element at mobile widths.

- [ ] **4. One auth network round-trip per answer** — Performance
  `src/composables/useStats.ts:88,110`
  `recordAnswer` calls `supabase.auth.getUser()` before every insert. Unlike
  `getSession()`, `getUser()` revalidates the JWT against the auth server rather
  than reading local storage — a 44-question run costs 44 extra sequential
  round-trips before 44 inserts. `useAuth.ts` already holds a module-level
  `user` ref kept current by `onAuthStateChange`; the data is in memory.
  *Secondary risk:* `correctCount++` happens after those awaits, and
  `recordAnswer` is fire-and-forget in `QuizPanel.handleSubmit:180`.
  `completeRun()` writes `correct: correctCount` on the next click, so on a slow
  connection the final answer can land after the write and store a score short
  by one.
  **Fix:** read `user` from `useAuth()`. Await `recordAnswer`, or track the tally
  outside the async path.

- [ ] **5. Sheet and reading-tips type ignores the reader's font-size setting** — WCAG 1.4.4
  `sheet.css:11` `clamp(11px, 0.75vw, 14px)`, `reading-tips.css:8`
  `clamp(13px, 0.9vw, 16px)`
  Both bases are px, so raising the browser font size changes nothing in the two
  densest surfaces — the ones most in need of it. Everything nested inherits in
  `em`, so at the 11px floor `.section-note` and `.legend-note` land at 8.25px
  and `.gloss` at 8.8px. The rest of the app honours the preference through the
  `--fs-*` rem ladder; these two opt out.
  DESIGN.md is explicit that em-derived sheet ratios are deliberate and that
  density is not to be apologised for. **The finding is the px basis, not the
  ratios** — `clamp(0.6875rem, 0.75vw, 0.875rem)` renders identically at default
  settings while restoring the preference. Directly relevant to a low-vision
  learner, who can still do this product's core task.

- [ ] **6. `lang` attributes are invalid, so `locl` never fires** — WCAG 3.1.2
  `MainMenu.vue:65,66,78,79`, `ScriptView.vue:68` → `ScriptPanel.vue:57`,
  `RoadmapView.vue:62`, `ScriptProgressList.vue:27` — all `:lang="script.id"`
  Verified in-browser via `Intl.getCanonicalLocales`:

  | Rendered | Result | Should be |
  |---|---|---|
  | `lang="thai"` | **throws** — 4-letter primary subtag is structurally invalid | `th` |
  | `lang="cyrillic"` | well-formed, not a registered subtag | `und-Cyrl` (a script, not a language) |
  | `lang="arabic"` | not a registered subtag | `ar` |
  | `lang="bengali"` | not a registered subtag | `bn` |
  | `lang="greek"` | not a registered subtag | `el` |
  | `lang="lao"` | ✅ canonicalises to `lo` — the one accidental hit | `lo` |

  This violates the project's own rule (CLAUDE.md: *"Codes are BCP-47… they must
  stay valid BCP-47"*). Practical blast radius is smaller than the table
  suggests: the affected sites are sidebar and panel-title native names, where
  `locl` substitution matters least, and the hand-written `lang="ru"` /
  `lang="sr"` in `cyrillic/ReadingTips.vue` — where it matters most — are
  correct. Worth fixing because it is cheap and because the rule exists to stop
  exactly this from spreading to a site where it does matter.

  **2026-08-03 recorded "`lang` attributes are correct BCP-47 and doing real
  work (OpenType `locl`)" as a positive finding. That was wrong** — asserted,
  not validated. Ticking this closes a false positive as well as a bug.

  **Fix:** add a `lang` field to `ScriptConfig` rather than reusing `id`. The two
  are different things, which is exactly why reusing one for the other broke.

- [ ] **7. A deep-linked tab opens off-screen on mobile**
  `src/components/ScriptPanel.vue:136-148` (`.tabs`)
  Verified at 390×844: loading `/scripts/thai?t=Mn4w` (info tab 2) lands with
  `scrollLeft: 0` and the active "Identify by shape" plate **0% visible**. The
  user never touched the strip, so nothing scrolled it.
  **Scope is only this entry path.** Normal interaction is fine, verified:
  swiping the strip then tapping leaves the tab **99% visible**, and keyboard
  `End` moves `scrollLeft` 0 → 214 with the focused tab **100% visible**,
  because `.focus()` scrolls into view natively.
  **Fix:** `scrollIntoView({ inline: 'nearest', block: 'nearest' })` on the
  active tab on mount, so `?t=` links land correctly. A `watch` on `activeIndex`
  is not needed — the browser and the user already cover the other paths.

- [ ] **8. Figure image shifts layout on load** — Performance (CLS)
  `src/scripts/cyrillic/ReadingTips.vue:256-260`
  `loading="lazy"` and a good alt, but no `width`/`height`. With
  `width: 100%; height: auto` the box is 0px tall until the bytes arrive, then
  jumps to ~400px — measured 592px rendered against `naturalWidth: 0`.
  Reading-tips prose reflows under the reader mid-sentence.
  **Fix:** intrinsic `width`/`height` attributes, or `aspect-ratio` on
  `.reading-tips figure img`.

- [ ] **9. `.btn-primary` is redeclared in five files** — Theming
  `QuizPanel.vue:490`, `TypeInQuiz.vue:166`, `StatsPanel.vue`, `RunsPanel.vue`,
  `ProgressView.vue`
  DESIGN.md defines `button-primary` as a system component; the implementation
  has five independent copies of the same nine declarations. They agree today.
  Also `color: #fff` appears 11 times where `--c-cell` is the token for exactly
  that value.
  **Fix:** one shared button class or a `BaseButton` component.

- [ ] **10. Silent clipboard failure** — Implementation Integrity
  `ScriptView.vue:52`
  `navigator.clipboard.writeText()` has no `.catch()`. On denial or an insecure
  context the promise rejects unhandled and the button still flips to
  "✓ Copied" — the user is told the link is on their clipboard when it isn't.

### P3 — polish

- [ ] **11. Toggle state is not exposed to assistive tech** — WCAG 4.1.2
  `QuizPanel.vue:215-249` (mode pills, sampling pills), `QuizShell.vue:66-77`
  (quiz/stats/runs bar), `MainMenu.vue:38` (sidebar toggle)
  Four groups of buttons carry a `.active` class with no `aria-pressed`,
  `aria-current` or radiogroup semantics, so state is fill colour alone.
  `ScriptPanel.vue` already implements the APG tablist correctly; these four
  places just don't use the pattern that exists.
  **Low priority by product reasoning** — see
  [How these are prioritised](#how-these-are-prioritised). Costs a sighted user
  nothing.
  Two parts are still worth doing cheaply:
  - The sidebar toggle's accessible name is the literal glyph `›`
    (`.toggle-icon` is not `aria-hidden`), so it announces as a punctuation
    mark. `aria-hidden="true"` plus `aria-label` is a two-attribute fix.
  - No `forced-colors` handling exists anywhere (verified: zero matching rules
    in any stylesheet), and active vs inactive rests on `background` + `color`
    with `border-width: 0` on both. Forced-colors overrides exactly those two
    properties, so in Windows High Contrast the active plate likely flattens
    into its neighbours. **Untested** — worth ten minutes in a real HCM session,
    because it hits low-vision users who *can* do the core task.

- [ ] **12. `transition: all 0.15s`** in `QuizPanel.vue:392` and
  `StatsPanel.vue:282` — transitions layout properties alongside colour. Name
  the two properties, as every other transition in the codebase does.
- [ ] **13. Hard-coded DOM id** — `id="tolerance-slider"` in `TypeInQuiz.vue:102`
  where `ScriptPanel` uses `useId()`. No collision today; inconsistent with the
  established pattern.
- [ ] **14. Progress bar has no `role="progressbar"`** (`QuizPanel.vue:263`).
  Mitigated — the adjacent `.progress-label` carries the same "n / m" as text.
- [ ] **15. `coming-soon` scripts are `<div>`s with a `title`**, so keyboard
  users never reach the "coming soon" explanation. Inertness is the right call
  (and 2026-08-03 correctly praised it); the label just isn't available without
  a pointer.
- [ ] **16. `.reading-tips code { font-family: monospace }`** — the bare keyword
  triggers the browser's monospace size quirk (13px default in Chrome), so
  inline code renders smaller than the `0.9em` intends.

## Patterns & systemic issues

- **Compounding `em` with no floor.** The same mechanism produces 4.95px
  CharBadge chips, 7px LangBadge chips, 8.25px legend notes and 8.8px section
  headers. Each individual `0.6em` or `0.75em` is reasonable; three multiplied
  against an 11px clamped base are not. The system has a documented *type ramp*
  but no documented *minimum* — the Shrinking Scale Rule guards the top of the
  ladder and nothing guards the bottom. This is 2026-08-03 finding 9 (9–10px
  micro-labels), now measured deeper and found worse. **The single highest-value
  fix in this audit is a floor.**
- **Colour drift is concentrated, not systemic.** Two components hold every
  undocumented colour in the codebase. LangBadge is licensed — CLAUDE.md
  documents D3 Category 20 as a deliberate categorical palette for
  distinguishing many languages, and that reasoning holds. CharBadge has the
  same shape with none of the justification. The remaining ~60 files are
  disciplined, which is why Theming scores 3 rather than 2.
- **State is expressed visually but not programmatically**, in four places. One
  missing convention rather than four bugs, and ScriptPanel's tablist already
  shows what the convention should be. Deliberately parked at P3.

## Positive findings — preserve these

- **The handout metaphor is executed, not asserted.** The consonant sheet is the
  artifact DESIGN.md describes — ruled, banded, tabulated, dense without being
  cramped. It would print.
- **No shadows. None.** Not one `box-shadow`, `filter`, `backdrop-filter`,
  gradient or `will-change`. Depth runs entirely on the hairline → tonal fill →
  plate ladder as documented.
- **Font loading is now quietly excellent.** 97 `@font-face` declarations across
  11 families, and the home route fetches **4 files / ~1 kB** — Fontsource's
  `unicode-range` subsetting doing its job. An 11-family picker system that
  costs nothing at rest. This was the last audit's worst finding.
- **Tab-strip scroll behaviour is correct as built.** Swipe-then-tap holds
  position; keyboard focus scrolls into view natively. Only the deep-link entry
  path is uncovered (finding 7).
- **ScriptPanel's tablist** is a correct WAI-ARIA APG implementation — manual
  activation with a documented rationale, roving tabindex, wraparound arrows,
  Home/End.
- **Focus management after submit and on tab return** is correct in three
  places, and the screen-reader verdict live region (`QuizPanel.vue:212`) is
  more care than this product owed.
- **Contrast in the core palette holds up.** The only failures measured are in
  the two badge components. The DESIGN.md contrast table is accurate everywhere
  it could be checked against the running app.
- **The accent-teal `h2` at 3.89:1 is not counted as a finding** — DESIGN.md
  argues the APCA case and records it as a knowing trade-off. A real tension,
  and one that has been reasoned about.

Findings 1, 2, 3 and 7 came from computed-style and `getBoundingClientRect`
sampling via the Playwright MCP server, not the detector. Finding 6 was checked
with `Intl.getCanonicalLocales` in the page. Finding 2's table was computed
offline against `LangBadge`'s `ORDER` and `D3_CATEGORY20` arrays.

**Simulate the gesture, not the handler.** The first pass of this audit called
finding 7 a P1 covering every tab interaction, because it switched tabs with
`element.click()` — which does not scroll the strip the way a thumb or a
`.focus()` call does, so the measurement produced the very condition it then
reported. Anything measured about a scroll container has to be driven the way a
user drives it.

**Devtools noise:** running against `npm run dev` puts a
`vue-devtools__anchor-btn` overlay near the bottom-centre of the viewport. It
looks like a stray glyph overlapping the QuizShell tab bar at 390px. It is not
yours.

**Note:** Playwright MCP writes screenshots to the *project root* unless given an
absolute path under `.playwright-mcp/`, and it rejects paths outside the project.
