The band label is harsher than the codebase deserves. The score is dragged by

work. Fixing those two moves this to 17–18.

### Implementation Integrity Verdict — PASS

Not interchangeable with another product. The character cell, the two-register
chrome/quiz split, the plate motif, the scrollbar-measuring sidebar, the
ruled-grid negative-margin trick are specific solutions to specific problems, and
the code comments explain *why* rather than *what*. Zero shadows across the whole
codebase is a held position, not an accident. The detector's 193 findings are
almost entirely the deferred type-ramp gap plus two legitimate categorical
palettes — **none are drift**.

## Findings

Tick these off as they land.

### P1 — fix before release

- [x] **1. Unlabelled font `<select>`** — WCAG 4.1.2 / 3.3.2
  `src/scripts/thai/FontPicker.vue`, `src/scripts/cyrillic/FontPicker.vue`
  The visible "FONT" text is a `<span>`, not a `<label for>`. Screen readers
  announce an unnamed combobox. Confirmed in live DOM:
  `unlabelledInputs: [{ type: "select-one" }]`.
  **Fix:** real `<label>`, or `aria-label="Font"`.

- [x] **2. Answer input has placeholder but no label** — WCAG 3.3.2
  `src/components/quiz/TypeInQuiz.vue:53`
  `placeholder="Type romanisation…"` is not an accessible name — it disappears on
  input and isn't reliably announced. This is the most-used control in the product.
  **Fix:** visually-hidden `<label>` or `aria-label`.

- [x] **3. Tab pattern declares ARIA it doesn't implement** — WAI-ARIA APG
  `src/components/ScriptPanel.vue:30-45`
  Measured live: **10 tabs, all in tab order, no roving tabindex, ArrowRight moves
  nothing.** Declaring `role="tab"` promises arrow-key navigation; a keyboard user
  must press Tab 10 times to cross the strip, and the roles actively mislead —
  currently *worse* than plain buttons.
  **Fix:** arrow-key handling + roving `tabindex`, or drop the roles.

- [x] **4. Empty `<h1>` on every script page** — WCAG 1.3.1
  `src/views/ScriptView.vue:79` + `src/components/ScriptPanel.vue:25`
  The practice panel gets no `title` prop, so it renders
  `<h1><span class="panel-name"></span></h1>`. Verified: `{ tag: "H1", text: "(EMPTY)" }`.
  The page also has two `h1`s, and neither tablist has an `aria-label` to
  distinguish info from practice.
  **Fix:** give the practice panel a title (e.g. "Practice"), or make the heading
  conditional.

- [x] **5. 13 render-blocking font stylesheets on every page** — Performance
  `index.html:11-24`
  Measured on the **home page**, which uses only Lora and Noto Sans:
  ```
  fontCssRequests:  13     renderBlockingLinks: 14
  fontFileRequests: 17     FCP: 588ms (localhost)
  ```
  Thai, Cyrillic, Arabic, Bengali, Pacifico and Great Vibes all download before
  first paint on a page that shows none of them. On real latency this multiplies,
  and it's 30 requests to Google per visit — which also enlarges the privacy
  exposure already disclosed on `/privacy`.
  **Fix:** load the two UI families eagerly; load script fonts per-route (the font
  pickers already know which is active).

### P2 — next pass

- [x] **6. All quiz datasets load on every route** — Performance
  `src/scripts/scripts.ts:4-5`
  `scripts.ts` statically imports `thaiDatasets` and `cyrillicDatasets`;
  `MainMenu` imports `scripts.ts`; `App.vue` imports `MainMenu`. So
  `scripts-*.js` — **60 kB raw / 21 kB gzip of question data** — is on the
  critical path for the About page. Notable because every *component* is properly
  lazy via `defineAsyncComponent`; only the data isn't.
  **Fix:** move dataset imports behind the same async boundary as the tabs using them.

- [ ] **7. Two categorical palettes are undocumented** — Theming
  `src/scripts/thai/CharBadge.vue:40-49`, `src/components/LangBadge.vue`
  23 of the 54 `design-system-color` findings are CharBadge's Thai taxonomy
  colours (obsolete / rare / vowel / short / long / mid / high / low) — a real,
  coherent semantic system, just absent from DESIGN.md. LangBadge's D3 Category 20
  is in the same position. **Documentation gap, not hard-coding.**
  **Fix:** document both as categorical palettes in DESIGN.md.

- [ ] **8. Touch targets below 44px** — WCAG 2.5.5 (AAA)
  Measured at 390px: toolbar pills 65×23, Link button 56×23, inline resource links
  18px tall. Defensible for a desktop-first product and AA doesn't require 44px —
  but it's the concrete reason mobile feels fiddly.

- [ ] **9. Micro-labels below the 11px legibility floor** — Accessibility
  `beta-badge` at **9px**, FontPicker's "FONT" at **10px**. The detector's own rule
  notes that being on the DESIGN.md ramp wouldn't exempt these — **the deferred
  ramp work won't resolve this one.**

- [x] **10. `border-radius: 3px` in 4 places** — Theming
  Outside the documented 2px/4px scale. `beta-badge` in two files plus two others.
  Trivially collapsible.

### P3 — polish

- [x] **11. No `prefers-reduced-motion` support** — low impact given the system's
  restraint (0.15s transitions); the sidebar width and progress-bar animations are
  the two that would matter.
- [ ] **12. `transition: width`** in `MainMenu.vue:160` and `QuizPanel.vue:369` —
  animates a layout property. Both small elements; real cost near zero.
- [ ] **13. No `loading="lazy"`** on `bulgarian-vs-russian-cyrillic.png`, which sits
  below the fold in Cyrillic reading tips.

## Patterns & systemic issues

- **Form controls are the consistent a11y gap.** Three of four inputs lack
  accessible names; the tolerance slider *is* correctly labelled, so the pattern
  already exists — it just wasn't applied.
- **Lazy loading was applied to components but not data.** One line per script, not
  a refactor.
- **Font loading is the only real performance problem** and it lives entirely in
  `index.html`.

## Positive findings — preserve these

- **Contrast reasoning encoded in the token layer**, with comments explaining the
  accent/sign split. Measured: Body Ink 9.1:1, Deep Ink 13.9:1, Faded Ink 4.8:1 —
  all pass AA.
- **Focus management is genuinely thoughtful** — global `focus-visible` ring,
  switched to `outline-offset: -2px` for controls flush against panel edges so the
  ring stays inside the surface. Most codebases don't do this.
- **Code splitting is exemplary** — 30+ route/tab chunks, most under 8 kB;
  201 kB / 54 kB gzip entry for Vue + Router + Supabase. Build in 1.11s.
- **No horizontal overflow at 390px**, achieved with `clamp()` rather than
  breakpoint stacking.
- **`lang` attributes are correct BCP-47** and doing real work (OpenType `locl`).
- **Coming-soon items are inert `<div>`s, not disabled links** — correct.

## How to reproduce

```sh
npm run dev                      # :5173

# static scan (clean — no devtools noise)
node .claude/skills/impeccable/scripts/detect.mjs src/

# rendered scan; use preview not dev, so vite-plugin-vue-devtools
# doesn't inject findings that aren't yours
npm run build && npm run preview          # :4173
node .claude/skills/impeccable/scripts/detect.mjs http://localhost:4173/scripts/thai
node .claude/skills/impeccable/scripts/detect.mjs http://localhost:4173/ --viewport 390x844
```

Browser inspection needs the Playwright MCP server (`--headless --executable-path`
→ `~/.cache/ms-playwright/chromium-1208/chrome-linux64/chrome`). The detector's own
URL scanning uses `puppeteer` + `PUPPETEER_EXECUTABLE_PATH`, set in
`.claude/settings.local.json`.

**Note:** Playwright MCP writes screenshots to the *project root*, not
`.playwright-mcp/`. Pass explicit paths or clean up after.
